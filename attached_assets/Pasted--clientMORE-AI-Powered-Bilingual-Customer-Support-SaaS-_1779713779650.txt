# clientMORE — AI-Powered Bilingual Customer Support SaaS
## Clean MVP Build Specification for Replit Agent

**Version:** 2.0 (Replit Build Edition)
**Date:** 2026-05-25
**Purpose:** Complete spec to build a production-ready MVP from scratch — no legacy code, no partial implementations, no known bugs.

---

## OVERVIEW

**clientMORE** is a B2B SaaS platform that lets any Arabic or English business deploy an AI support bot in under 10 minutes. The bot reads the company's uploaded documents, answers customer questions across Web widget, Telegram, and WhatsApp, and escalates to human agents when it can't answer. Unanswered questions feed a learning loop — agents teach the bot with one click.

**The one-line pitch:** Replace expensive, slow human support with a bot that speaks Arabic, knows your business, and never sleeps.

---

## TECH STACK (NON-NEGOTIABLE)

### Backend
- **Runtime:** Python 3.11+
- **Framework:** FastAPI (async)
- **Database:** SQLite with SQLAlchemy ORM (WAL mode enabled)
- **Vector Store:** ChromaDB (persistent, local)
- **Task Queue:** None for MVP (inline async is fine)
- **Auth:** JWT (HS256, python-jose), bcrypt password hashing
- **Encryption:** Fernet (cryptography library) for secrets stored in DB
- **LLM Chain:** Google Gemini → DeepSeek → OpenAI (try in order, skip if key missing)
- **Embeddings:** Google `text-embedding-004` → OpenAI `text-embedding-3-small` → MD5-hash fallback
- **File parsing:** PyMuPDF (PDF), python-docx (DOCX), openpyxl (XLSX), plain text (TXT/MD)
- **Telegram:** python-telegram-bot (long-polling, not webhook)
- **WhatsApp:** Twilio Python SDK (webhook)
- **Rate limiting:** slowapi

### Frontend (Admin Dashboard)
- **Framework:** Next.js 14 (App Router)
- **Language:** TypeScript
- **Styling:** Tailwind CSS
- **UI Components:** shadcn/ui
- **Charts:** Recharts
- **State:** React hooks (no Redux)
- **HTTP:** fetch API (no axios)
- **Real-time:** native WebSocket

### Deployment (Replit)
- Backend runs on port **8000**
- Frontend runs on port **5000** (next dev -p 5000)
- Both in the same Replit project as separate processes
- All secrets via **Replit Secrets** (environment variables)

### 1. chat_service.py — Main Pipeline

```
handle(tenant_key, session_id, channel, user_message) → str:

1. get_or_create_conversation(tenant_key, session_id, channel)
2. detect_and_cache_language(conversation, user_message)
3. if conversation.status == "handoff":
     return localized "Our team will reply shortly" message
4. if active PurchaseOrder for this conversation:
     return advance_purchase_state_machine(order, user_message)
5. classify_intent(user_message, settings):
     - contains keywords ["اشتري","أطلب","order","buy"] → PURCHASE_INTENT
     - contains ["تشكوى","شكوى","complaint","problem","مشكلة"] → COMPLAINT
     - contains ["بشري","موظف","human","agent","انسان"] → SUPPORT_REQUEST
6. if intent == PURCHASE_INTENT and settings.purchase_flow_enabled:
     create PurchaseOrder, return first collection prompt
7. if intent == COMPLAINT and settings.auto_handoff_on_complaint:
     create_handoff(conversation, "complaint"), return escalation message
8. if intent == SUPPORT_REQUEST:
     create_handoff(conversation, "support_request"), return escalation message
9. RAG pipeline:
     a. if no documents exist for tenant:
          create_handoff("empty_kb"), return escalation message
     b. chunks = hybrid_search(tenant_key, user_message, k=5)
     c. confidence = max(chunk.score for chunk in chunks)
     d. if confidence < settings.confidence_threshold:
          create_handoff("low_confidence"), return escalation message
     e. answer = generate_answer(user_message, chunks, conversation_history, settings)
     f. if answer contains NO_ANSWER_SENTINEL:
          create_handoff("low_confidence"), return escalation message
10. persist Message(role="user"), Message(role="assistant", content=answer)
11. log AnalyticsEvent
12. broadcast WebSocket update to dashboard
13. return answer
```

### 4. ingest_service.py — File Processing

```python
CHUNK_SIZE = 800       # characters
CHUNK_OVERLAP = 100    # characters

def process_file(tenant_key, doc_id, file_path, file_type):
    raw_text = extract_text(file_path, file_type)
    chunks = sliding_window_chunk(raw_text, CHUNK_SIZE, CHUNK_OVERLAP)
    # Filter empty chunks
    chunks = [c.strip() for c in chunks if len(c.strip()) > 50]
    ingest_chunks(tenant_key, doc_id, chunks)
    return len(chunks)

def extract_text(path, file_type) -> str:
    if file_type == "pdf":   return pymupdf_extract(path)
    if file_type == "docx":  return python_docx_extract(path)
    if file_type == "xlsx":  return openpyxl_extract(path)
    if file_type in ("txt", "md"): return open(path).read()
```

## MULTI-CHANNEL: TELEGRAM

```python
# backend/services/telegram_service.py

# On startup: if is_telegram_active for any tenant, start polling
# Use python-telegram-bot Application with token per tenant

async def handle_telegram_message(update, context, tenant_key):
    chat_id = update.effective_chat.id
    text = update.message.text
    session_id = f"tg:{chat_id}"
    reply = await chat_service.handle(tenant_key, session_id, "telegram", text)
    await context.bot.send_message(chat_id=chat_id, text=reply)

def send_telegram_message(token: str, chat_id: str, text: str):
    url = f"https://api.telegram.org/bot{token}/sendMessage"
    requests.post(url, json={"chat_id": chat_id, "text": text})
```

## PURCHASE FLOW STATE MACHINE

```
States: collecting_product → collecting_quantity → collecting_address → pending_confirmation → confirmed

collecting_product:
  Bot: "ما اسم المنتج الذي تريد طلبه؟"
  User input → save product_name → move to next state

collecting_quantity (if purchase_collect_quantity):

collecting_address (if purchase_collect_address):
  Bot: "ما هو عنوان التوصيل؟"
  User input → save delivery_address

pending_confirmation:
  Bot: "ملخص طلبك: {product} × {qty} — التوصيل إلى: {address}. هل تأكد الطلب؟ (نعم/لا)"
  "نعم" → state = "confirmed" → create Handoff with order metadata
  "لا" → cancel order, return to normal RAG mode
```

## SECURITY REQUIREMENTS (ALL MANDATORY)

1. **Admin routes** — every route in `admin.py` must use `Depends(require_admin_key)`. The dependency compares the `X-Admin-Key` header using `hmac.compare_digest()` (constant-time). Return 401 if missing, 403 if wrong.

2. **JWT auth** — every dashboard API route (except `/api/chat`, `/api/auth/*`, widget settings) must use `Depends(require_jwt)`. Decode token, verify expiry, attach `current_user` to request.

3. **Demo login** — `/api/auth/demo-login` must issue a real JWT for a real demo tenant row. No sessionStorage bypasses. Token expiry: 2 hours for demo.

4. **Secrets in DB** — Telegram tokens and Twilio credentials encrypted with Fernet before INSERT. Decrypted on use. Never returned in API responses (return masked version only).

5. **File upload** — validate MIME type + extension match. Reject executables. Save to temp path with random UUID name, not original filename.

6. **CORS** — allow only `http://localhost:5000` in development. In production, set to actual frontend domain.

7. **Rate limiting** — 30 requests/minute per IP via slowapi on `/api/chat`. 10/minute on auth endpoints.

8. **Tenant isolation** — every DB query filters by `tenant_key` from the JWT. Never trust `tenant_key` from request body for protected endpoints.

## GRACEFUL DEGRADATION

| Condition | Behavior |
|-----------|----------|
| No LLM API keys | Use MD5 hash embeddings + return top matching chunk verbatim |
| Gemini fails | Try DeepSeek, then OpenAI |
| All LLMs fail | Create handoff: "Our system is temporarily unavailable, connecting you to a human" |
| ChromaDB unavailable | Return handoff response, log error |
| No documents uploaded | Return handoff with reason "empty_kb" |
| Confidence below threshold | Return handoff with reason "low_confidence" |
| Telegram delivery fails | 3 retries (1s, 2s, 4s), mark handoff delivery_status="failed" |
| WebSocket disconnects | Client auto-reconnects up to 10 times with exponential backoff; after 10 failures, show "Live updates paused" banner |

## GLOSSARY

| Term | Definition |
|------|-----------|
| **RAG** | Retrieval-Augmented Generation — search the knowledge base, then pass results to the LLM to generate a grounded answer |
| **Handoff** | A conversation escalated from the bot to a human agent |
| **Deflection Rate** | % of questions answered by the bot without human involvement |
| **Tenant** | A business using clientMORE (one subscription = one tenant) |
| **Tenant Key** | Unique slug for a tenant, e.g. `"shop_123"` |
| **Chunk** | ~800-character text segment from an uploaded document |
| **Confidence Score** | `1 - cosine_distance / 2` — 0.0 = unrelated, 1.0 = perfect match |
| **ChromaDB** | Open-source vector database storing document embeddings |
| **Keyless Mode** | No API keys set — uses MD5 hash embeddings and returns top chunk verbatim |
| **Fernet** | Symmetric encryption (AES-128-CBC + HMAC) used to encrypt secrets stored in DB |
