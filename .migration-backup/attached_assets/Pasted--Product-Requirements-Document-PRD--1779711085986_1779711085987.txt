   11 ## 1. EXECUTIVE SUMMARY
   12
   13 **clientMORE** is a B2B SaaS platform that enables businesses to deploy an
      intelligent, bilingual (Arabic/English) customer support bot in minutes. Th
      e bot learns from the company's own documents, answers customer questions a
      cross Web, Telegram, and WhatsApp, and seamlessly escalates to human agents
       when it doesn't know the answer. Every unanswered question becomes a learn
      ing opportunity — admins can teach the bot with one click, making it smarte
      r over time.
   14
   15 **The core promise:** Replace or augment expensive human support teams with
       a bot that speaks your language, knows your business, and never sleeps.

  451 ### 7.1 System Overview
  452
  453 ```
  454 Customer Device
  455      │
  456      ├── Web Browser ──────── Next.js Widget (/widget) ──────────┐
  457      ├── Telegram App ──────── Telegram Bot (long-poll) ──────────┤
  458      └── WhatsApp App ──────── Twilio Webhook (/whatsapp/webhook) ┤
  459                                                                    ↓
  460                                                     FastAPI Backend (:8000)
  461                                                            │
  462                                ┌───────────────────────────┼───────────────
      ────────────┐
  463                                ↓                           ↓
                  ↓
  464                           SQLite DB                   ChromaDB
              LLM Provider
  465                          (backend.db)              (chroma_store/)
         (Gemini/DeepSeek/OpenAI)
  466                     Documents, Messages,           Embedded Knowledge
              RAG Generation
  467                     Handoffs, Settings,            Base + User Memory
              + Embeddings
  468                     PurchaseOrders, Tenants
  469
  470 Admin Dashboard ── Next.js Frontend (:5000) ── REST API + WebSocket ──→ Fas
      tAPI Backend
  471 ```
  472
  473 ### 7.2 Request Flow (Web Chat)
  474
  475 ```
  476 1. Customer sends message → POST /api/chat
  477 2. chat_service.handle():
  478    a. Get or create Conversation
  479    b. Detect language (cache per conversation)
  480    c. Check if already in handoff → return "agent will reply" message
  481    d. Check if active purchase order → advance purchase state machine
  482    e. Classify intent (keyword + optional LLM):
  483       - PURCHASE_INTENT → start purchase flow
  484       - COMPLAINT + auto_handoff_on_complaint → create Handoff
  485    f. RAG fallback:
  486       - Check if KB is empty → create Handoff
  487       - Hybrid search (vector + lexical) → top-K chunks
  488       - Confidence gate → create Handoff if too low
  489       - Generate answer via LLM (Gemini → DeepSeek → OpenAI)
  490       - Validate answer → create Handoff if no-answer sentinel
  491 3. Persist message + any state changes
  492 4. Return response JSON
  493 5. Broadcast dashboard update via WebSocket
  494 ```

  586 ## 8. NON-FUNCTIONAL REQUIREMENTS
  587
  588 ### 8.1 Performance
  589 - API response time (chat): p50 < 1.5s, p95 < 3s
  590 - Vector search: < 200ms for k=3 over 10,000 chunks
  591 - Frontend initial load: < 2s (Lighthouse score > 80)
  592 - WebSocket reconnection: < 3 seconds after disconnect
  593
  594 ### 8.2 Scalability
  595 - SQLite is sufficient for up to ~100 concurrent tenants
  596 - ChromaDB single-writer limit: run seeding BEFORE server, not concurrently
  597 - For > 100 tenants: migrate to PostgreSQL + Qdrant/pgvector
  598 - Rate limiting: 30 requests/minute per IP (via slowapi)
  599
  600 ### 8.3 Security
  601 - All API keys stored in env/Replit Secrets — never in code or DB (exceptio
      n: Fernet-encrypted channel tokens in DB)
  602 - JWT tokens: HS256, 24h expiry
  603 - Admin routes: require `X-Admin-Key` header (constant-time comparison)
  604 - Webhook signature checks: optional but available for Telegram and Twilio
  605 - Password hashing: bcrypt with cost factor 12
  606 - CORS: only allow frontend origin(s)
  607 - Next.js security headers: X-Frame-Options, CSP, HSTS, no-sniff (already c
      onfigured)
  608
  609 ### 8.4 Reliability
  610 - Graceful degradation: if LLM API fails, fallback to next provider in chai
      n
  611 - Keyless mode: app boots and demos with zero API keys
  612 - Database: SQLite with WAL mode for better concurrent reads
  613 - Handoff delivery: 3 retries with exponential backoff (1s, 2s, 4s)
  614
  615 ### 8.5 Accessibility & Internationalization
  616 - RTL layout support for Arabic (already implemented via `isRtl` context)
  617 - Google Fonts: Inter (English) + Cairo (Arabic)
  618 - All strings in i18n translations object — no hardcoded text
  619 - Keyboard navigation for dashboard forms
  620 - Color contrast: WCAG AA minimum (dark theme with purple accents)

      oaded document for indexing |

       search |

      knowledge is to the customer's question; derived as `1 - cosine_distance /
      2` |

      wer; below this, escalate to human |

      MPLAINT, SUPPORT_REQUEST, GENERAL) |

      ocument chunks |

      tion; used to personalize responses but never used as a KB source |
  742 | **Keyless Mode** | Operating mode where no API keys are set; uses MD5 has
      h embeddings and returns top chunk verbatim |
